## 발견한 미해결 이슈

### QA-003 · 저장 응답 전 체크박스 재클릭이 유실됨

**근거: 실제 1.1.2 설치본 + 설정 저장 응답에 600ms 지연 주입, 독립 모의 검사.**

재현 순서:

1. 줄바꿈의 `기존 줄바꿈 보존`이 체크된 상태에서 시작한다.
2. `STORE_DATABASE_DIFF`의 처리 시작을 검수 패널 안에서 600ms 늦춘다. 네트워크 지연이나 네이버의 실패를 가정한 검사가 아니라 로컬 설정 저장 대기 검사다.
3. 체크박스를 누르고 30ms 후 같은 체크박스를 다시 누른다.
4. 두 저장 요청이 끝난 뒤 화면과 실제 `chrome.storage.local`을 읽는다.

기대: 체크 해제 → 다시 체크하여 처음 값 `true`로 돌아간다.

실제: 두 번 모두 이전 `checked=true` 상태에서 해제 요청이 생성된다. 클릭 직후 화면도 `true`로 되돌아가고, 저장이 끝나면 `false`가 남는다. 실제 값은 다음과 같았다.

```json
{"delayMs":600,"before":true,"afterFirstClick":true,"afterSecondClick":true,"requests":2,"afterWrites":false,"stored":false,"expectedAfterTwoClicks":true,"settingsRestored":true}
```

구현 근거: `src/ui/RulesEditor.tsx:11`의 controlled checkbox는 저장된 props를 사용하며, `src/ui/App.tsx:83`은 저장 완료 후에만 `db`를 갱신한다. 정상 속도의 단일 클릭, 글쓰기 새로고침 후 값 유지, 패널 재열기 후 프리셋 체크박스 6종의 켜기/끄기는 통과했다. 따라서 **새로고침만 하면 모든 체크박스가 고장 난다는 결론은 아니다.**

### QA-004 · 이전 글의 지연된 성공 응답이 새 글의 패널 상태를 덮어씀

**근거: 실제 App 컴포넌트 + 모의 편집기/지연 응답 검사. 네이버 실환경에서 같은 지연 순서는 미확인.**

1. A 세션에서 서식 적용을 시작하고 응답을 보류한다.
2. B 세션으로 이동한 스냅샷을 패널에 반환한다.
3. A 세션의 성공 응답을 늦게 반환한다.

기대: 패널이 B 세션 상태를 유지한다.

실제: A의 스냅샷이 다시 표시되고, B에서 작업하지 않았는데 A의 `되돌리기`가 활성화된다. `src/ui/App.tsx:84`의 작업 성공 경로는 새 세션의 조회가 이미 완료됐는지 검사하지 않고 응답을 반영한다. 실제 다른 글의 본문이 수정되거나 유실된 사례를 이 검사로 입증한 것은 아니다. 지연된 A의 **실패** 응답이 B를 계속 잠그는 대조 검사는 통과했다.

### QA-005 · 단축키 결과의 창 확인 응답 순서가 바뀌면 최신 상태가 역전됨

**근거: 실제 App 컴포넌트 + chrome.windows.getCurrent 지연 모의 검사. 실제 OS 키 입력의 해당 타이밍은 미확인.**

아래 두 순서를 각각 재현했다.

- 이전 단축키 결과 수신/창 확인 대기 → 최신 단축키 결과 반영 → 이전 창 확인 완료.
- 이전 단축키 결과 수신/창 확인 대기 → B 세션 연결 조회 완료 → 이전 창 확인 완료.

두 경우 모두 이전 결과가 뒤늦게 반영되어 최신 선택·되돌리기 상태가 교체됐다. 구현 근거는 `src/ui/App.tsx:63-73`이며, 수신 시점의 순서가 아닌 창 확인 완료 시점에 `snapshotSerial`을 증가시킨다. 기존에 검사하던 **먼저 시작한 poll이 단축키 성공을 덮어쓰는 경우**와 반대 방향이다.

## 자동 검사와 재현 방법

- 기존 `npm test`: **50개 파일, 702개 테스트 통과**. 현재 실행 결과이며 과거 기록을 재사용하지 않았다.
- 추가 진단: **8개 중 4개 통과, 4개 실패**. 실패 4개는 위 미해결 이슈 3개에 해당한다(QA-005가 2개 시나리오).
- `npm run check`, `npm run verify`, `npm run spec:check`: 통과.
- 별도 진단 소스도 원본 tsconfig를 확장한 임시 설정으로 TypeScript 검사를 통과했다. 실패한 진단은 타입 오류가 아니라 위 동작 불일치에 따른 assertion 실패다.
- 제품 소스/manifest를 변경하지 않아 빌드·패키지 재생성은 수행하지 않았다.

추가 진단 파일은 기본 회귀 테스트 목록과 별도로 보존했다. 미수정 오류를 찾는 검사라 현재 실패가 예상되며, 기본 702개 테스트가 모두 통과하는 것과 구분한다.

```sh
npx vitest run --config scripts/live-qa/qa-112.config.ts
```

재현 소스: `scripts/live-qa/qa-112.test.tsx`, 설정: `scripts/live-qa/qa-112.config.ts`.

추가 로컬 원시 관찰 자료는 무시되는 `artifacts/qa-112-20261110/`에 있다. 이 보고서와 진단 소스에 핵심 재현 조건을 보존했으므로 해당 폴더만을 필수 근거로 삼지 않는다.
