# 빠른 선택·서식 적용 안정화 검증

2026-11-10, 원본 작업 경로 `/Users/msyu/study/geulbugi`. OpenSpec change: `improve-fast-editing-reliability`.

로컬 1.1.2 빌드(어댑터 v44)의 결과다. 스토어 버전 배포·제출·커밋·푸시는 수행하지 않았다. 별도 clone/worktree는 만들지 않았다.

## 수정한 동작

1. **체크박스 재클릭 유실**: 설정을 즉시 표시하고 저장은 순서대로 처리한다. 늦은 첫 응답이 최신 조작을 덮어쓰지 않는다. 저장 실패 시 실제 저장값으로 복원하며, 실패한 이전 필드를 다음 저장에 끼워 넣지 않는다.
2. **이전 글 응답의 패널 덮어쓰기**: 문서 연결 세대와 마지막 확정 결과를 확인해, 다른 글로 이동하거나 더 최신 결과가 도착한 뒤 이전 작업 응답을 반영하지 않는다. 연결 해제 후 같은 글로 돌아오는 경우도 검사한다.
3. **단축키 창 조회의 순서 역전**: 비동기 창 확인 전에 결과 수신 순서를 예약한다. 늦은 창 확인이 최신 단축키 결과나 새 문서 상태를 덮어쓰지 않는다.

추가 실환경 검수에서, 복원한 네이버 원고의 DOM 선택 앵커가 제목에 남는 경우를 발견했다. 서식 시작 시 현재 선택을 즉시 캡처하고, 네이티브 선택 원문과 화면 하이라이트의 위치·크기가 본문 범위 한 곳에 모두 일치할 때만 이 앵커를 보완한다. 불일치·중복 후보는 계속 차단한다. 실제 본문 DOM을 직접 고치지 않는다.

## 줄인 지연과 유지한 안전 장치

- 선택 추적 중 변경 없는 본문 읽기를 최대 100ms 재사용하고 동일 선택 알림을 생략한다. 본문·상속 서식 변경, 레이아웃 변경 시 무효화하며, 적용·undo·결과 검증의 `read()`는 항상 현재 본문 전체를 읽는다.
- 긴 문단의 커서는 브라우저가 찾은 후보의 실제 기하 정보와 인접 모호성을 확인한다. 양방향 문자·방향 제어 문자가 있는 문단은 비인접 경계의 모호성을 놓치지 않도록 전체 탐색을 유지한다. 확인할 수 없으면 기존 전체 경계 탐색으로 돌아간다.
- 패널은 마지막 이벤트 뒤 500ms를 계속 기다리는 대신 80ms 단위로 갱신한다. 조회 중 알림은 후속 조회 한 번으로 합치고 5초 연결 확인도 유지한다.
- 단축키마다 최신 설정·프리셋을 읽되, 관계없는 저장 글 전체를 매번 검증하지 않는다. 일반 저장·가져오기·백업 검증은 유지한다.
- 서식의 중복 읽기와 마지막 100ms 고정 대기를 줄였다. 네이티브 도구의 일반 80ms 안정화 확인은 유지한다.
- 대기 중 입력 또는 다음 서식은 **요청한 서식 전체, 제목·원문·사진·선택 밖 서식이 이미 검증된 경우에만** 앞 작업에서 인계한다. 부분 적용·미확정 결과에는 적용하지 않는다. 일반 재시도 큐나 다른 프레임으로의 중복 실행을 추가하지 않았다.
- 직접 입력 후에는 그 입력을 지우는 자동 undo를 하지 않는다. 정확한 기존 revision이 유지될 때만 일반 되돌리기를 허용한다.

하단 80글자 미리보기는 유지했다. 앞선 A/B 계측에서 미리보기 숨김의 개선 근거가 없었고, 주요 비용은 선택 추적·반복 읽기·고정 대기였다.

## 자동 검증

최종 코드에서 `npm run check`, `npm test`, `npm run build`, `npm run verify`, `npm run spec:check` 모두 통과했다. Vitest **55개 파일, 739개 테스트**, OpenSpec **7개 항목** 통과.

새 회귀 검사는 `fast-editing-state`, `fast-settings-save`, `panel-refresh-performance`, `selection-performance`, `fast-format-input`에 있다. `input-buffer-selection`에는 오래된 제목 앵커와 하이라이트의 일치·불일치·모호성 검사 3개를 추가했다. 기존 원문·사진·선택 밖 서식 보존, 부분 적용·지연 변경·복구 차단·undo 검사가 함께 통과했다.

별도 진단 설정 `scripts/live-qa/qa-112.config.ts`(8개)와 `qa-112-performance.config.ts`(2개)도 통과했다. 이 진단 결과와 실제 네이버 실행을 구분한다.

## 실제 설치본·네이버 검증

Ego Chromium에 로컬 `dist/`를 압축 해제 설치해 네이버 테스트 전용 원고를 사용했다. 어댑터 `naver-one-public-ui-v44`, 설치 표시 버전 1.1.2를 확인했다. 네이버 저장·발행 버튼은 누르지 않았다. 네이버의 자동 복원 안내에서는 검수용 제목을 확인한 원고만 복원했다.

단축키가 사용하는 실제 background → content → 네이버 공개 UI 경로로 서식을 실행했다. **OS 전역 키 조합 자체의 종단 검증은 미완료**다. 브라우저 자동 키 입력은 Chrome command를 발생시키지 않았고, 원래 키 배정도 비어 있었다. 임시 배정은 제거했다. 실제 command 이벤트의 원래 탭·최신 설정 처리와 응답 순서는 자동 회귀 검사로 검증했다. Windows·Chrome 116·다른 네트워크 환경의 검수도 이 결과에 포함하지 않는다(`QA-002`).

검수 전후 `chrome.storage.local`의 DB와 `chrome.commands.getAll()`을 비교해 **설정·프리셋·저장 글·키 배정 모두 정확히 일치**했다. 주입한 지연은 제거했다. 로컬 확장과 개발자 모드는 검수 전의 꺼짐 상태로 돌렸고, 전용 브라우저 TaskSpace와 이번 작업에서 시작한 8774 포트 임시 서버를 종료했다. 다른 작업의 서버·프로세스는 종료하지 않았다.
