# 0.1.9 단축키 검증

2026-10-07 · 설치 버전 0.1.9 · Ego Lite · 검수 공간 2.

## 자동 검증

`npm test`: **19파일 · 258개 검사 통과**. `npm run check`: 타입 검사 통과.

`tests/shortcut-routing.test.ts`에서 실제 background 모듈이 등록하는 `chrome.commands.onCommand` 리스너를 Chrome API 경계 모의 객체로 검사했습니다. 추가 검사 15개는 기본 슬롯 1~4의 저장된 서식, 사용자 지정 슬롯 5~8, 다음 실행에서 변경된 매핑 다시 읽기, 삭제·미지정 명령 무시, 선택 오류 전달, 끊어진 이전 프레임 건너뛰기, 응답 유실 후 중복 적용 방지, 등록된 편집기가 없을 때 편집 방송 방지, 읽기 전용·다른 사이트에서 편집하지 않기를 포함합니다.

이 검사는 운영체제의 물리 키 입력을 대체하는 통과 증거가 아닙니다. 기존 자동 검사 243개에는 여러 문단의 선택·서식 경계 보존과 인용구 변환 검사도 포함됩니다.

## 실제 브라우저 확인

새 전용 초안 **블로그 편집 도우미 0.1.9 단축키 검수 2026-10-07**을 임시 저장했습니다. 네 문단 중 첫째 문단 offset 16부터 셋째 문단 offset 18까지 실제 마우스로 선택했습니다. 준비 시 리비전은 `7f56e3f0`입니다.

기존 실제 키 조합은 비어 있었습니다. Chrome 단축키 설정 화면에서 다음 네 조합을 등록하고 `chrome.commands.getAll()`과 저장된 프리셋 매핑으로 확인했습니다. 최종 실행 범위는 모두 **ego에서(CHROME)**이며 슬롯 5~8은 미지정 상태입니다. 프리셋 값은 변경하지 않았습니다.

| 키 조합 | 명령 | 저장된 서식 |
| --- | --- | --- |
| ⌥⇧1 | apply-preset-1 | 본문 |
| ⌥⇧2 | apply-preset-2 | 소제목 |
| ⌥⇧3 | apply-preset-3 | 강조 |
| ⌥⇧4 | apply-preset-4 | 인용구 · 말풍선 |

페이지용 키 입력은 Chrome의 확장 명령 이벤트를 호출하지 않았습니다. 별도 일반 브라우저 창에서 운영체제 키 입력으로 `apply-preset-1` 이벤트가 한 번 발생했지만, 검수 초안이 대상 창이 아니어서 편집기 연결 오류로 끝났습니다. 이 시도는 서식 적용 통과로 기록하지 않습니다.

검수 공간의 에이전트 제어 상태에서는 운영체제 키 입력이 편집기 또는 확장 명령에 도달하지 않았습니다. 실행 범위 하나를 임시로 전체(GLOBAL)로 바꿔 진단했으나 명령이 발생하지 않아 CHROME으로 복원했습니다.

사용자의 재개 요청 후 CUA의 macOS 실제 키 입력으로 검사를 이어갔습니다. 페이지에 전달한 키 이벤트와 구분해 `chrome.commands.onCommand` 호출과 최종 `SHORTCUT_RESULT` 응답을 대조했습니다. 모든 명령의 실제 대상은 검수 탭 `1513316541`·검수 창 `1513316537`이었습니다.

| 실제 키 검사 | 선택 | 완료 응답의 리비전 | 복원 |
| --- | --- | --- | --- |
| ⌥⇧1 · 본문 | 첫 문단 16~셋째 문단 18 | `65397bb3` | 원본 서식으로 정확히 복원 |
| ⌥⇧2 · 소제목 | 같은 세 문단 부분 선택 | `b166a2fe` | 네이버 ⌘Z 3회로 정확히 복원 |
| ⌥⇧3 · 강조 | 같은 경계의 역방향 선택 | `bb7a23b3` | 네이버 ⌘Z 2회로 정확히 복원 |
| ⌥⇧4 · 인용구 | 같은 세 문단 부분 선택 | `c2d6a451` | 네이버 ⌘Z 5회로 정확히 복원 |

본문 단축키의 복원은 확장의 되돌리기 버튼으로 확인했습니다. 후속 복원은 네이버의 네이티브 되돌리기를 사용하고 각 키 입력 뒤 원문·문단 서식·글자 서식이 기준 상태와 같아졌을 때 멈췄습니다. 공개 DOM 비교에서는 동적인 id와 선택 표시 클래스만 제외했습니다. 같은 원본의 어댑터 리비전 `7f56e3f0`은 확장 되돌리기 경로에서도 다시 확인했습니다.

일반 서식 3종에서 선택 전·후 글자의 15px·검은색·굵기와 마지막 문단을 보존했습니다. 소제목은 저장된 16px·가운데 정렬·굵게·`#141414`, 강조는 저장된 15px 유지·굵게·`#0078cb`로 적용됐습니다. 인용구는 처음 세 문단 전체를 하나의 네이버 말풍선 인용구로 묶고 마지막 문단을 보존했습니다. 네이버의 빈 ‘출처 입력’ 자리표시는 원문에서 제외해 비교했습니다.

커서만 둔 상태에서 ⌥⇧3을 입력하면 ‘서식을 적용할 글자를 먼저 선택해 주세요.’라는 오류 응답을 반환했고, 원문과 서식은 그대로였습니다.

추가 커서 인용구 시도 한 번은 완료 응답을 기다리기 전에 네이버 되돌리기를 시작했습니다. 일시적인 DOM에서는 현재 문단 하나만 인용구로 바뀌고 나머지 문단이 보존됐으나, 최종 응답은 보존 검사 실패·복원이었으므로 **단축키 성공 집계에서 제외**했습니다. 같은 커서·저장된 프리셋의 편집 요청을 실제 패널 버튼에서 완료까지 기다려 재검사했을 때는 `7f56e3f0` → `e4d96b87` → `7f56e3f0`으로 적용·정확한 복원이 통과했습니다. 이 보조 결과를 물리 단축키 통과로 대체하지 않습니다.

마지막에는 정상 완료된 세 문단 말풍선 인용구 예시를 새 검수 초안에 임시 저장했습니다. 최종 리비전은 `c2d6a451`입니다. 최종 네이티브 패널의 되돌리기 버튼도 활성 상태로 확인했습니다. 공개 발행은 하지 않았습니다.
