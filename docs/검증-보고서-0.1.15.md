# 예약 요청 연결 오류 · 0.1.15

2026-10-11 · 어댑터 `naver-one-public-ui-v27`.

예약 적용 시 “지원하지 않는 편집 요청이에요”가 표시되는 연결 문제를 수정했습니다. 확장 관리 화면에서 설치된 버전이 0.1.13이고 로드 위치가 이 저장소의 `dist`인 것을 확인했습니다. 파일 교체 후 패널은 새로운 코드를 읽어도, 확장과 열린 글쓰기 프레임은 이전 코드를 실행할 수 있습니다.

## 변경

- 스냅샷의 `capabilities`로 예약 지원 여부를 확인합니다. 기능이 없는 글쓰기 프레임에는 예약 요청을 보내지 않습니다.
- 이전 프레임이 연결돼 있으면 예약 적용을 비활성화하고 초안 임시저장 → 확장 새로고침 → 글쓰기 탭 새로고침 순서를 안내합니다. 확장 관리 화면을 여는 버튼을 제공합니다.
- 이전 백그라운드의 일반 미지원 오류도 예약 요청에 한해 갱신 안내로 바꿉니다.
- 기능 메타데이터가 없는 0.1.14의 어댑터 v27은 계속 지원합니다. 같은 문서에 다시 연결되면 고른 날짜·시간도 유지됩니다.

## 자동 검사

전체 **425개 / 31개 파일**과 타입·빌드·패키지 검사를 통과했습니다. 신규 8개 검사는 이전 프레임에 대한 예약 전송 차단, 지원 프레임의 단일 전송, 0.1.14 호환, 명시적 미지원, 응답 유실 시 재전송 방지, 이전 백그라운드 오류 안내, 패널 재연결과 선택 유지, 이전 예약 버전의 패널 적용을 확인합니다.

근거: `tests/editor-routing.test.ts`, `tests/schedule-panel.test.tsx`. 프레임 교체와 이전 버전의 조건은 모의 메시지 응답으로 검사했습니다.

## 설치된 확장의 실제 요청 검수

Ego Lite TaskSpace 50에서 설치된 확장을 관리 화면의 새로고침 버튼으로 **0.1.15**로 갱신하고 새 글쓰기 탭에서 기존 사진 검수용 초안을 불러왔습니다.

설치된 `sidepanel.html`을 검수 탭으로 열어 예약 패널의 실제 버튼 이벤트를 실행했습니다. 이 탭이 네이버 탭의 활성 상태를 가져가지 않도록 검수용 네이버 탭을 Chrome API로 명시적으로 활성화했습니다. 실제 사이드 패널의 도킹 동작은 이 검사에 포함하지 않습니다. 확장 런타임 → 백그라운드 → 설치된 글쓰기 콘텐츠 스크립트의 전체 경로를 사용했으며 어댑터 번들을 페이지에 별도로 주입하지 않았습니다.

- 런타임 버전 **0.1.15**, 프레임의 `publish-time` 지원 보고를 확인했습니다.
- **예약 설정 적용** 버튼으로 `2026-10-12 09:00`을 요청했고 네이버의 예약 라디오·날짜·시·분이 일치했습니다.
- 성공 안내가 표시됐으며 적용 전후 본문 리비전과 사진 블록 전체가 같았습니다.
- **현재 발행으로 전환** 버튼으로 검수 초안을 복원했습니다. 예약 시간 기본값·자주 쓰는 시간의 의미상 값도 유지했습니다.
- 최종 발행을 실행하지 않았습니다. 검사한 탭 3개는 종료 시 닫았습니다.
