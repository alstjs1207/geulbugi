# 1.0.4 최근 글 페이지 오류 대응

검증일: 2026-10-29 (KST). 원본 `/Users/msyu/study/geulbugi`에서 수정했다. 별도 worktree·clone·임시 서버는 사용하지 않았다.

## 재현과 판단

사용자 오류: “내 블로그의 최근 글 목록을 확인하지 못했어요. 다시 시도해 주세요.”

이 문구는 최근 글 URL 검증에서 발생한다. 첫 페이지만 조회하는 이전 백그라운드를 모의하고 현재 10개 조회 패널을 연결했을 때 요청 1·2페이지 중 두 번째에 같은 문구를 재현했다. 실제 네이버 첫 페이지 응답을 사용했다. 반면 현재 백그라운드와 연결한 정상 경로는 네이버에서 1~4페이지를 읽고 고유 글 10개를 반환했다.

사용자의 실행 중인 확장 백그라운드는 직접 확인하지 못했다. 따라서 이전 코드 잔존은 재현된 원인 후보이며, 사용자의 실제 원인으로 확정하지 않는다. 설치 버전·방식 확인을 요청했다.

## 변경

- 동일한 1.0.3 이름으로 패키지를 교체하던 흐름을 끝내고 설치 버전을 1.0.4로 올렸다. 기존 ZIP과 별도 파일로 전달한다.
- 요청한 다음 페이지 대신 첫 페이지가 반환되면 확장 새로고침 안내와 ‘확장 관리 열기’ 버튼을 표시한다. 성공할 수 없는 재시도를 반복하게 하지 않는다.
- 첫 페이지 URL의 `currentPage` 생략은 1페이지로 처리한다. 이 URL을 다음 페이지의 응답으로 인정하지 않으며 다른 블로그·호스트·카테고리 검증도 유지한다.
- 최근 공개 글 최대 10개와 검색 최신순 기능은 유지한다.

## 검증

- `npm run release`: 46개 테스트 파일, 647개 테스트, 타입 검사, 빌드, 패키지 검증, ZIP 생성 성공.
- 현재 조회·네트워크 코드를 실제 익명 네이버 응답에 연결해 요청 페이지 `[1,2,3,4]`, 반환 10개, 고유 URL 10개를 확인했다. DOMParser와 Chrome 메시지 전달만 로컬 모의로 연결했다.
- 구버전 백그라운드 재현, 생략된 첫 페이지 매개변수, 다른 페이지·블로그 거부, 관리 화면 열기 회귀 테스트를 추가했다.
- 사용자 브라우저의 확장을 교체·새로고침하는 조작은 수행하지 않았다. 사용자가 기존 dist 설치를 갱신한 뒤 정상 동작을 확인했고 스토어 배포를 요청했다. 실제 오류 원인은 원격으로 확정하지 않는다.

## 산출물과 적용

설치용 ZIP: `artifacts/geulbugi-1.0.4.zip`. 로컬 설치 폴더: `dist/`.

압축 해제 설치는 기존에 로드한 폴더의 파일을 새 패키지로 교체하고 패널을 닫은 뒤 `chrome://extensions`에서 글부기를 새로고침하고 다시 연다. 확장 삭제·재설치는 필요하지 않다. 원본 프로젝트·브랜치는 유지했으며 커밋·푸시는 수행하지 않았다. 이후 사용자 승인으로 2026-10-29 스토어 업로드와 심사 제출을 완료했고, 상세 상태는 `스토어-1.0.4-20261029.md`에 기록했다.
