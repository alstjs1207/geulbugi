## 원인과 변경

실제 네이버 내 블로그에서 프로필 글쓰기는 `/<blogId>/postwrite`를 `mainFrame`에 연다. 상단 주소는 `/<blogId>?Redirect=Write&`로 바뀌지만 내부 편집기는 postwrite 경로를 유지한다. 본문 `.se-canvas .se-components-wrap`에는 contenteditable이 없고 별도 `input_buffer...` iframe의 body만 편집 가능하다.

기존 reader는 본문 내부의 contenteditable 또는 PostWriteForm/PostUpdateForm 경로로 편집 가능 여부를 판단했다. 따라서 프로필 경로는 루트·본문을 읽어도 editable=false였다. 실제 DOM을 반영한 회귀 검사에서 수정 전 이 경로만 실패함을 확인했다.

- `src/editor/reader.ts`: 실제 편집기 루트가 있을 때 정확한 `/<blogId>/postwrite` 경로를 인식한다. 부분 일치 경로·공개 글·루트 없는 로딩 화면을 편집 가능으로 확대하지 않는다.
- `src/background.ts`: 프레임 등록을 session 저장소에 반영한 뒤 PANEL_REFRESH를 보낸다. 기존 패널의 80ms 갱신 합치기·5초 주기 확인을 이용한다.
- `tests/reader.test.ts`, `tests/editor-routing.test.ts`: 프로필/레거시 경로, 공개 조회/유사 경로/로딩 화면, 등록 저장 후 갱신 순서를 검사한다.

원고·사진·사용자 입력, 작업 실행과 중복 실행 방지, 저장 형식과 권한을 변경하지 않았다.
