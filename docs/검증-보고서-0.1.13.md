# 0.1.13 사진 선택창 무반응 수정과 업로드 검수

2026-10-11 · 확장 **0.1.13** · 어댑터 **naver-one-public-ui-v26**.

0.1.12의 새 사진 버튼에서 파일 선택창이 열리지 않는 문제를 재현했습니다. 확장 요청으로 네이버 사진 버튼을 자동 클릭하면 숨겨진 업로드 입력은 생기지만 선택창은 열리지 않았습니다. 같은 초안에서 네이버 버튼을 직접 클릭하면 선택창과 PNG 업로드가 정상 작동했습니다.

패널의 실제 클릭 안에서 파일 선택창을 동기적으로 열도록 변경했습니다. 선택 후 파일을 네이버 사진 버튼이 새로 만든 공개 파일 입력에 전달하고 change 이벤트를 한 번 보냅니다. 선택 당시의 문서·세션·리비전·삽입 위치를 확인하며 파일을 저장하지 않습니다. 한 번에 20장·합계 20MB 제한은 확장의 JSON 메시지 전송 한도입니다.

여러 파일은 네이버의 공개 개별사진 옵션을 자동 선택해 순서대로 추가합니다. 선택 취소·재선택은 본문을 바꾸지 않습니다. 선택창을 닫은 후 선택 중 상태가 남은 경우를 위한 사진 선택 취소 버튼도 제공합니다. 업로드한 모든 사진의 실제 주소·수량·위치를 기다려 기존 글·서식·사진·캡션을 비교합니다. 임시 이미지나 일부 파일만 나타난 상태에서는 완료나 undo를 허용하지 않습니다. 비동기 사진 삽입 실패에는 자동 undo를 사용하지 않습니다.

## 자동 검사

`npm run release` 통과: 타입 검사, **28파일·384개 검사**, 빌드, Manifest V3·권한·필수 파일 검사, ZIP 생성. ZIP 무결성 검사도 통과했습니다.

추가 검사는 클릭 안의 동기적인 선택창 열기, 파일 취소·재선택·중복 전달 방지, 클릭 당시 대상 유지, 파일 순서·포맷별 바이트 전송, 잘못된 자료·수량·용량 거부, 20MB 전송 자료 복원, 새 네이버 업로드 입력 확인, 기존 팝업 보호, 여러 파일의 개별사진 선택, 빈 문단 DOM 재생성, 임시 이미지·단계별 업로드 대기, 원문·캡션·제목·위치 보존, 업로드 실패 시 사용자 글·이전 undo 보호를 포함합니다. 기존 링크 지연·검색·선택·줄바꿈 검사도 통과했습니다.

## 실제 네이버 확인

Ego Lite의 기존 설치본을 갱신하고 새 전용 초안 **블로그 편집 도우미 사진 업로드 검수 2026-10-11**을 사용했습니다. 검증용 600×400 PNG 두 종류를 업로드했습니다. 패널 페이지의 실제 새 사진·취소·되돌리기 버튼을 사용했으며 파일 전달과 편집 요청 동안 네이버 글쓰기 탭을 활성 상태로 유지했습니다. 해당 전용 초안만 임시저장했습니다.

네이버 저장본은 업로드 당시 파일 이름을 가진 이미지 alt 속성을 빈 값으로 바꿉니다. 따라서 저장 전 `923387d6`과 재열기 후 `8ed3985d`의 전체 리비전은 다릅니다. 서버 비교에서는 파일 이름 alt와 빈 채움 문단을 제외하고 원문·서식·사진 주소·크기·수량·순서·캡션을 대조해 일치를 확인했습니다. 이를 전체 리비전 일치로 처리하지 않았습니다.

중간 검수에서 여러 파일을 선택하면 네이버의 사진 첨부 방식 창에서 멈추는 것을 발견했습니다. 이 창을 그대로 둔 초기 수정본은 2분 뒤 완료 미확인 상태를 안내했고 기존 본문을 지우지 않았습니다. 최종 빌드는 개별사진을 자동 선택해 이 대기를 해결했으며 위 표의 두 장 삽입·정확한 undo를 다시 확인했습니다. 비교 실험의 중간 실패도 원본 기록에 남겼습니다.

실제 업로드는 PNG로 확인했습니다. JPG·JPEG·GIF·BMP·HEIC·HEIF·WebP는 파일 전송의 자동 검사 범위이며 모든 포맷의 네이버 서버 업로드를 실기로 통과 처리하지 않았습니다. 기존 사진의 이동·콜라주·슬라이드·단축키도 이번 실기 확인 범위에 포함하지 않습니다.
