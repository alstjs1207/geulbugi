## 문단 클릭과 글자 선택

글자 서식과 링크는 실제 글자 선택·커서 범위를 확인합니다. 네이버 input buffer의 범위와 공개 커서 표시를 대조하며 FEFF 시작·끝 표식만 제외합니다. 이벤트 직후 늦게 갱신되는 커서는 60ms 뒤 다시 읽습니다.

인용구에는 정확한 글자 오프셋 대신 클릭한 문단을 사용할 수 있습니다. 본문의 같은 문단에서 누름·뗌이 끝났을 때 문단과 원본 서명을 기억합니다. 문단 내용·서식이 바뀌거나 문단을 넘는 드래그는 클릭 대상을 무효화합니다. 출처 문단은 별도 클릭 대상으로 사용하지 않습니다.

여러 문단 선택은 input buffer 안에 복제된 `.se-text-paragraph`의 공개 DOM id로 본문과 연결합니다. 첫 문단의 접미부·중간 문단의 전체 원문·마지막 문단의 접두부를 비교하고 연속 순서를 확인합니다. BR은 LF로 읽고 NBSP는 위치·길이가 같은 공백으로 비교합니다. 텍스트를 임의로 합쳐 전역 검색하지 않으며 보호 요소를 건너뛰지 않습니다. 패널로 포커스가 이동해도 입력 frame의 원래 Range를 복원합니다.

인용구 실제 적용 전에는 공개 포인터로 마지막 문단 끝으로 이동하고 Shift+ArrowLeft로 포함된 문단 전체를 선택합니다. grapheme 단위로 이동하고 문단 경계 이동과 실제 네이버 선택 범위가 전체 원문과 같은지 확인합니다. 공개 변환 도구가 나타날 때까지 기다린 다음 하나의 인용구로 변환합니다. 여러 문단의 굵기는 선택된 모든 run을 확인합니다. 범위가 다르면 변경을 시작하지 않습니다. DOM 선택만 바꿔 네이버 모델의 선택을 추측하지 않습니다.

## 링크 미리보기 카드

링크는 본문의 접힌 커서를 사용합니다. 글자가 없는 문단은 공개 커서 표시와 문단의 실제 줄 영역을 대조해 오프셋 0으로 기억합니다. 키보드로 다른 문단으로 옮긴 경우에도 실제 커서가 있는 문단을 찾습니다. 이미 같은 위치라면 native input buffer의 Range를 복원하므로 빈 글자 사각형을 억지로 클릭하지 않습니다. placeholder는 본문 글자와 위치 계산에서 제외합니다.

네이버의 공개 ‘링크 추가’ 버튼을 누르고 `.se-popup-oglink`의 URL 입력·검색·확인 버튼을 사용합니다. 미리보기 제목과 썸네일을 최대 15초 기다린 뒤 확인을 한 번 눌러 카드만 삽입합니다. 본문에 URL을 붙여넣거나 선택·삭제 키를 보내지 않습니다. 새 카드가 미리보기의 제목·요약과 일치하고 미리보기에 있던 썸네일도 표시됐는지 확인한 뒤 주소를 연결합니다.

확인 전에는 원래 문서와 리비전을 대조합니다. 로딩 중 실제 사용자 키보드·포인터 입력, 본문 변경, 창 닫기, URL 변경은 삽입을 취소합니다. 조회 실패 시 이 작업이 연 링크 창만 닫으며 본문은 변경하지 않습니다. 링크 실패에는 자동 undo를 사용하지 않으므로 로딩 사이에 입력된 사용자 글이나 이전 붙여넣기 이력을 지우지 않습니다. 확인 후 삽입 결과가 불확실하면 본문을 그대로 두고 초안을 다시 열 때까지 추가 작업을 막습니다. 성공한 삽입의 명시적인 되돌리기는 이전과 같이 정확한 리비전을 확인합니다.

`.se-oglink`의 공개 `data-linkdata`·href와 제목·요약·썸네일·도메인을 읽습니다. 실제 편집 카드에는 주소 속성이 없을 수 있으므로, 확장으로 삽입한 카드의 native component ID·정규 URL·제목/요약/도메인 해시만 별도 로컬 참조에 저장합니다. 본문은 저장하지 않으며 최대 1,000건을 유지합니다. 초안을 다시 열면 같은 component ID와 공개 카드 내용이 일치할 때만 주소를 복원합니다. 모바일·HTTP·추적 URL은 중복 확인용 정규 주소로 비교하고 일반 링크의 원래 glyph 서식은 보존합니다. 미리보기 설명을 본문 문단으로 중복 집계하지 않습니다. 카드 메타데이터도 리비전에 포함합니다.

결과에는 카드가 정확히 하나 추가되어야 하며 커서 앞뒤의 문구·서식·기존 구성 요소 순서가 유지되어야 합니다. 실제 네이버의 삽입·지연·취소·저장 검수는 [0.1.12 보고서](검증-보고서-0.1.12.md)에 기록합니다.

## 기존 사진 이동

`PublicEditorUI.movePhoto`는 기본 draggable 이미지와 공개 `.se-dnd-wrap`을 사용합니다. 마우스 선택으로 사진 묶음 전체 선택을 확인한 뒤 dragstart를 보내고, 대상 문단의 시작·끝 Range 좌표로 mousemove를 보냅니다. 공개 `.se-caret-drop` 위치가 해당 글자 경계와 일치해야 mouseup을 보냅니다. 네이버가 drop·dragend를 만들고 마우스·키보드 드래그 상태를 해제하며, 제출 전 실패는 Escape로 종료합니다. 직접 구성 요소 DOM을 옮기거나 내부 네이버 API를 호출하지 않습니다.

`verifyPhotoMove`는 선택한 사진만 옮긴 예상 전체 순서와 실제 원문·서식·사진·캡션·레이아웃을 비교합니다. 문단 ID 재생성과 빈 커서 문단을 허용하되 사진의 순서·수량·그룹을 지킵니다. 사진 읽기 서명은 캡션 서식·사진 레이아웃·모듈 크기·링크도 포함합니다. 이미 같은 위치면 요청을 변경 없음으로 처리합니다. 패널은 검증된 비사진 구성 요소 순서로 새 대상 ID를 연결합니다.

이동 중 본문이나 네이버 입력 프레임의 사용자 조작을 감시합니다. 제출 전 본문 변경이나 사용자 조작이 있으면 현재 내용을 자동 undo하지 않습니다. 사용자 개입 없이 자체 이동 결과가 보존 검사를 통과하지 못하면 원래 리비전까지 네이버 undo로 복원합니다.

## 새 사진 업로드

확장 메시지를 받은 뒤 네이버 사진 버튼만 자동 클릭하던 경로에서는 실제 선택창이 열리지 않았습니다. 패널의 실제 클릭 안에서 자체 파일 입력을 동기적으로 열고 파일을 선택한 후에 편집 요청을 보냅니다. 선택 취소는 요청을 보내지 않으며 사용자가 창을 닫은 경우 선택 상태를 직접 취소할 수 있습니다. 파일은 저장하지 않고 요청 메모리에서만 전달합니다. 한 번에 20장·합계 20MB 제한은 base64가 포함된 Chrome JSON 메시지 크기를 고려한 확장의 전송 제한입니다.

선택창을 열 당시의 세션·문서·리비전과 대상 앞뒤 위치를 기억합니다. 전달 전 현재 문서와 비교하고 공개 포인터로 대상을 지정합니다. 네이버 사진 버튼이 새로 만든 `input#hidden-file[type=file]`에 `DataTransfer`의 선택 파일을 설정하고 change 이벤트를 한 번 보냅니다. 기존 다른 파일 입력은 재사용하지 않습니다. 여러 파일은 네이버 공개 사진 첨부 방식 창의 개별사진 옵션을 한 번 눌러 순서대로 넣습니다. 내부 네이버 편집기·업로더 API는 사용하지 않습니다.

빈 임시 이미지나 일부 파일의 삽입을 완료로 판단하지 않습니다. 모든 선택 파일의 실제 이미지 주소·수량·순서를 기다린 뒤 목표 문단의 앞뒤 문구·서식·기존 사진·캡션·다른 구성 요소를 비교합니다. 문단 ID가 재생성되어도 공개 구성 요소와 내용의 순서로 확인합니다. 성공한 업로드의 명시적 undo는 원래 리비전에서 멈춥니다. 업로드 실패·도중 사용자 변경에는 자동 undo를 사용하지 않으며 2분 뒤에도 완료가 불확실하면 현재 본문을 유지하고 초안 재열기를 안내합니다.

실제 PNG 선택창·업로드·취소·앞뒤 위치·빈 문단·저장 검수는 [0.1.13 보고서](검증-보고서-0.1.13.md)에 기록합니다.

## 등록 없는 내 글 검색

기본 검색 대상은 네이버 `PostSearchList.naver`의 내 블로그 공개 검색입니다. service worker는 저장된 블로그 주소와 요청의 정규 주소가 일치할 때만 검색 URL을 직접 생성합니다. 쿼리와 페이지 번호를 검증하고 기존 네이버 블로그 호스트 권한 안에서 익명 GET을 실행합니다. 별도 서버·검색 API 키·로그인 쿠키를 사용하지 않습니다.

응답은 DOMParser로 읽으며 스크립트를 실행하지 않습니다. 공개 결과 건수와 `.s_link` 제목 링크, 같은 결과 행의 날짜·발췌, 공개 페이지 이동 정보를 읽습니다. 게시글 주소를 정규화하고 내 블로그 글만 목록으로 반환합니다. 형식을 알 수 없는 응답을 0건으로 취급하지 않습니다.

검색은 검색 버튼·Enter·추천 검색어 클릭으로 실행합니다. 결과는 현재 패널 메모리에만 유지하며 기존 등록 자료에 추가하지 않습니다. 다음 페이지는 정규 URL로 중복을 제거해 누적합니다. 네트워크 실패 시 기존 페이지를 보존하고 실패한 페이지를 다시 요청합니다. 요청 번호와 블로그 주소로 늦은 응답을 무시하며 블로그 주소 변경 시 이전 결과를 폐기합니다. 검색 결과의 미리보기 삽입은 기존 링크 요청을 사용합니다.

기존 자료는 ‘저장한 글’에서 로컬 검색과 현재 글 키워드 추천을 유지합니다. URL 등록·열린 글 등록·파일 가져오기는 선택적인 보조 기능입니다.

## 적용 결과와 되돌리기

검사 기록·블로그 주소·문서 제목·이전 세션의 통과 여부와 무관하게 편집을 요청할 수 있습니다. 링크는 내 글 범위를 확인하기 위해 블로그 주소를 사용합니다.

결과 비교와 일반 서식의 자동 복원은 유지합니다. 비동기 링크·사진 삽입 실패는 현재 본문을 유지합니다. 직전 작업의 적용 후 리비전이 현재 본문과 같을 때만 undo를 허용합니다. 네이버 이력의 보이지 않는 단계도 지나되 원본 리비전에 도달하면 멈춥니다. 무변경 요청·무변경 실패는 이전 undo를 보존합니다.

문서 읽기와 거부된 다른 요청은 진행 중인 작업 잠금을 해제하지 않습니다. 해당 변경을 시작한 호출만 잠금을 해제합니다. 업로드·사진 로딩·지연 입력·복원 실패는 별도 상태로 처리합니다.

## 저장 호환성

schemaVersion 1의 저장 필드는 `settings`, `presets`, `posts`입니다. 이전 `verifications`는 읽을 때 제외하며 다음 정상 저장에서 제거합니다. 사용자 설정·프리셋·게시글은 유지합니다. 사용자 테스트 요청 API와 테스트 결과 응답, 모양별 활성화 기준, 재열기 기록 갱신은 삭제했습니다.

개발 서버는 로컬 UI 검토 도구이며 설치된 확장은 별도 운영 서버 없이 실행합니다.

## 예약 발행 시간

`src/core/schedule.ts`는 한국 날짜·10분 단위·미래 시각 검증과 기본 시간 재사용을 담당합니다. `src/ui/SchedulePanel.tsx`는 날짜와 시간 선택, 자주 쓰는 시간 저장, 현재 네이버 설정, 적용 결과를 표시합니다.

`src/editor/publish-time.ts`는 공개 헤더의 `data-click-area="tpb.publish"` 버튼으로 설정을 열고 `radio_time`·네이버 달력·시간 select를 사용합니다. 읽기 전용 날짜를 직접 덮어쓰지 않습니다. 최종 `seOnePublishBtn`은 실행하지 않습니다. 달력 이동은 24개월 이내로 제한하고 네이버의 비활성 월·날짜를 거부합니다.

`NativeAdapter`의 `publish-time` 요청은 현재 문서·세션·리비전과 진행 중 작업을 확인합니다. 본문 변경 이력을 만들거나 기존 undo를 초기화하지 않습니다. 적용 중 사용자 입력 또는 문서 변경은 중단하며 설정 복원도 하지 않습니다. 다른 실패는 이전 공개 발행 시간만 복원합니다. 사진 지연 로딩은 예약 설정의 선행 조건이 아닙니다.

저장 설정의 `schedule`은 선택 필드이며 기존 schemaVersion 1 자료의 나머지 필드는 유지됩니다. UI는 변경한 기본 시간 또는 시간 목록만 저장하고 다중 창 저장도 필드별로 병합합니다. 날짜는 사용자 설정에 저장하지 않습니다.

예약 지원 여부는 스냅샷의 `capabilities`로 확인합니다. 메타데이터가 없는 0.1.14의 어댑터 v27도 허용합니다. 예약을 지원하지 않는 이전 프레임은 패널과 백그라운드의 읽기 전용 탐색에서 거부하며, 아직 이전 백그라운드가 응답할 때의 일반 미지원 오류도 구체적인 갱신 안내로 바꿉니다. 실제 예약 요청을 전송한 뒤 연결이 끊기면 다른 프레임에 재전송하지 않습니다.

## 0.1.17의 결과 읽기와 이력 보호

캡션의 포커스 배경과 편집 도구는 사진 서명에서 제외하며 실제 캡션 글자·정렬·스타일을 비교합니다. 네이버가 기본으로 붙이는 파일명 alt만 정규화하고 사용자 설명은 보존합니다. 사진 묶음 이동은 기존 단위 선택을 해제한 뒤 전체 선택을 확인하고, 네이버가 바꾼 사진 정렬은 공개 속성 메뉴로 복원합니다.

링크 창이 열리면서 수행하는 클립보드 URL 조회를 먼저 기다리고 요청한 URL을 조회합니다. 링크 삽입·undo가 화면 밖 사진을 지연 이미지로 재생성하면 공개 스크롤로 실제 주소를 다시 읽고 원래 스크롤 위치를 복원한 뒤 결과를 비교합니다. 이전 URL 캐시로 사진 보존을 추정하지 않습니다. 제한 시간 안에 로드되지 않으면 결과 확인을 안내합니다.

줄바꿈 Enter 전에는 input buffer의 실제 선택이 접혔는지 확인합니다. 기존 선택을 접을 때도 공개 커서와 선택 문자열의 시작·끝 경계를 대조합니다. undo는 매 단계에서 원래 글자·사진 파일·캡션을 확인하고 범위를 넘는 단계는 redo합니다. 묶음 분리·재결합의 중간 이력은 통과할 수 있지만 최종 복원은 정확한 원래 리비전으로 확인합니다.
