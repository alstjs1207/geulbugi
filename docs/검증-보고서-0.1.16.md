# 사진 이동 경로 오류 수정 · 0.1.16

2026-10-13 · 확장 **0.1.16** · 어댑터 **naver-one-public-ui-v28**.

## 원인과 변경

설치된 0.1.15 확장의 실제 편집 요청에서 “이 사진의 공개 이동 경로를 확인할 수 없어요. 본문을 변경하지 않습니다.”를 재현했습니다. 기존 코드는 사진 컴포넌트 안의 `[draggable="true"]`만 찾았습니다. 실제 네이버 사진에는 해당 속성이 없으며, 이미지 자체의 기본 draggable 동작을 네이버의 `.se-dnd-wrap`이 마우스 기반 드래그로 처리합니다.

사진을 네이버의 공개 마우스 이벤트로 선택하고 이미지의 dragstart를 보냅니다. 문단 시작·끝의 실제 글자 경계로 마우스를 이동해 네이버의 공개 이동 커서 위치를 확인한 후 mouseup으로 마칩니다. 네이버가 drop과 dragend를 만들고 마우스·키보드 드래그 상태를 해제합니다. 진단 과정에서 기존 방식처럼 문단 중앙 좌표에 drop을 보내면 문장이 중간에서 갈라지고, dragend만 보내면 네이버의 마우스 드래그 상태가 남는 것도 확인했습니다.

- 네이버가 대상 문단 DOM을 재생성해도 전체 내용·서식·사진 순서로 문단 앞·뒤 배치를 검증합니다. 빈 네이버 커서용 문단은 비교에서 제외합니다.
- 캡션 글자 서식·사진/묶음 레이아웃·모듈 크기·사진 링크도 읽기 서명에 포함합니다. 동일 이미지 주소를 가진 사진들이 있어도 사진 속성 전체의 집합을 비교합니다.
- 사진 묶음의 전체 선택을 확인한 뒤 이동합니다. 묶음 일부를 선택했거나 팝업이 열려 있으면 이동을 시작하지 않습니다.
- 이동 커서가 문단 경계와 다르거나 제출 전에 본문이 바뀌면 Escape로 네이버 드래그를 취소합니다. 본문·네이버 입력 프레임에서 사용자가 조작하면 자동 undo로 사용자 내용을 덮어쓰지 않습니다.
- 동일 위치 재요청은 변경 없음으로 처리하며 이전 undo 기록을 유지합니다. 실제 이동 후 새 문단 ID를 패널에 연결해 선택 문단 표시도 유지합니다.

## 자동 검사

전체 **446개 / 32개 파일**, TypeScript 검사, 빌드, 확장 패키지 검사와 ZIP 생성을 통과했습니다.

신규 `tests/photo-move-native.test.ts`의 **21개 검사**는 공개 마우스 드래그 경로, 앞·뒤 글자 경계, 대상 DOM 재생성, 사진 묶음 보존, 정확한 undo, 잘못된 이동 커서의 Escape 취소, 제출 전 사용자 내용 보존, 부분 선택 차단, 팝업 보호, 반복 요청의 undo 유지, 잘못된 본문 변경의 자동 복원, 위치·원문·서식·캡션·레이아웃·묶음·사진 중복·문단 구조·제목 보존, 선택 표시와 같은 문구의 문단 구별을 확인합니다. 네이버의 마우스 래퍼와 DOM 응답은 이 검사에서 모의 구현했습니다.
