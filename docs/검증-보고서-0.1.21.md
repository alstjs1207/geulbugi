# 0.1.21 사진 AI 활용 설정 일괄 ON

검수일: 2026-10-20 (Asia/Seoul). 확장 0.1.21, 어댑터 v38.

추가 실제 설치본 검수에서 발견한 문제를 0.1.22에서 수정했다. 최신 결과는 [0.1.22 설치본 검수](검증-보고서-0.1.22.md)를 참고한다.

## 변경 사항

사진 탭 상단에 **AI 활용 설정 일괄 ON**과 `ON 사진 수 / 전체 사진 수`를 추가했다. 현재 글의 개별 사진과 콜라주·슬라이드 묶음을 대상으로 하며 본문 선택은 필요 없다. 네이버의 `.se-set-ai-mark-button-toggle` 기본 버튼을 클릭하고 버튼의 `se-is-selected` 상태로 결과를 확인한다. 그룹 사진은 실제 네이버가 제공하는 묶음 토글을 한 번만 누르고, 포함된 사진 수로 집계한다.

이미 켜진 설정은 유지한다. 완료 후 모든 사진의 상태와 원문·서식·링크·캡션·사진 순서·묶음 구조 보존을 다시 비교한다. 정상 완료한 작업은 기존 네이버 실행 취소 경로로 되돌린다. AI 설정을 수동으로 바꾸어도 문서 리비전이 바뀌므로 이전 작업의 되돌리기로 덮어쓰지 않는다.

요청에 세션·문서·리비전을 포함한다. 오래된 탭, 사진 업로드 중, 사진 정보 미확인, 비활성·중복·누락된 토글은 적용 전에 차단한다. 사용자 입력이나 본문 변경이 있으면 중단한다. 부분 완료 시 현재 ON 수를 안내하고 현재 상태를 보존하며 재실행하면 OFF인 항목만 처리한다. 설정·프리셋의 저장 형식과 확장 권한은 추가하지 않았다.

## 자동 검사

`npm run release` 통과: 타입 검사, **532개 검사 / 40개 파일**, 빌드, 설치 패키지 검증, ZIP 생성. 기존 502개에 신규 30개 검사를 추가했다.

신규 검사는 개별·그룹·공유 토글, ON/OFF 혼합, 중복 실행과 undo 기록, 정확한 복원, 세션·문서·리비전 불일치, 토글 누락·중복·비활성, 응답 없는 토글의 부분 완료·재시도, 사용자 본문 보존, 업로드와 읽기 전용 차단, 빈 문서, 네이버 팝업, 수동 설정 후 undo 차단, 패널 상태·연결 갱신 안내·중복 클릭, 구버전 프레임 라우팅을 포함한다.

## 실제 네이버 편집기 확인

사용자 기존 임시저장 글을 열지 않고 새 검수용 글쓰기 탭에 예시 PNG를 업로드했다. 프로젝트 소스로 빌드한 개발 검수 어댑터를 해당 글쓰기 프레임에 연결해 공개 DOM과 기본 클릭·실행 취소 경로를 사용했다. 내부 편집기 객체나 비공개 저장 API는 사용하지 않았다.

| 문서 구성 | 적용 전 | 적용 후 | 보존 및 복원 |
| --- | --- | --- | --- |
| 개별 사진 2장 | 1/2 ON | 2/2 ON | 기존 ON 유지, 반복 요청 unchanged, 내용 보존, undo 후 원래 리비전 일치 |
| 개별 사진 2장 + 콜라주 2장 | 1/4 ON | 4/4 ON | 그룹 공유 토글 지원, 반복 요청 unchanged, 내용 보존, undo 후 원래 리비전 일치 |
| 개별 사진 2장 + 슬라이드 2장 | 1/4 ON | 4/4 ON | 그룹 공유 토글 지원, 내용 보존, undo 후 원래 리비전 일치 |

로컬 React 미리보기의 실제 사진 탭 버튼으로 `0/4 → 4/4 ON` 상태와 완료 안내를 확인했다. 사진 이동 UI와 버튼이 겹치지 않는 것도 스크린샷으로 확인했다.

확인 범위: 실제 네이버의 네이티브 동작은 개발 어댑터로, 패널은 로컬 미리보기로 검수했다. 설치된 Chrome 확장의 패널 → 백그라운드 → 콘텐츠 스크립트 전체 경로는 이번 실기 검수에 포함하지 않았으며, 요청 라우팅은 자동 검사로 확인했다. 발행·수동 임시저장을 실행하지 않았다.
