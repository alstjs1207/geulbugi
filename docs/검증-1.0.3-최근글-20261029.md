# 1.0.3 최근 글 조회·최신순 검색

검증일: 2026-10-29 (KST). 기존 배포 버전은 사용자 확인 기준 1.0.2. 이번 산출물은 로컬 설치·검토용 1.0.3이며 스토어에 제출하거나 배포하지 않았다.

## 동작

- 내 글 탭에 실제 진입하면 저장한 블로그의 공개 글 목록에서 최근 공개 글을 최대 10개 조회한다. 블로그가 한 페이지에 3개를 표시하면 4페이지까지 필요한 만큼 조회하고 10개에서 중단한다. 다른 탭에 머무를 때는 요청하지 않는다.
- 새로고침은 HTTP 캐시 없이 최근 글을 다시 조회한다. 탭에 다시 진입할 때도 조회한다. 주기적 수집·전체 글 수집·자료 자동 저장은 없다.
- 최근 목록에는 공지글과 본문 속 관련 글 링크를 제외하고 제목·작성일·원문 열기·기존 미리보기 삽입 버튼을 표시한다. 목록은 최대 10개이며 공개 글이 그보다 적으면 있는 만큼만 표시한다. 페이지 간 중복은 정규 URL로 제거한다.
- 검색은 `orderBy=date`로 요청한다. 같은 날짜 안의 순서와 다음 페이지 순서도 네이버 응답대로 유지한다.
- 최근 글 보기로 검색어를 비우고 최신 목록으로 복귀한다. 저장한 글의 기존 로컬 검색·추천은 유지한다.
- 새로고침 실패 시 직전 최근 목록을 보존한다. 검색·새로고침·블로그 변경·탭 이탈 시 늦은 응답이 다른 목록을 덮어쓰지 않는다.

## 검증 결과

- `npm run release`: 타입 검사, 전체 자동 테스트, 프로덕션 빌드, 패키지 검증, ZIP 생성 성공. 10개 확장 전 전체 검증 624개와 추가 정렬 회귀 테스트 2개가 통과했다. 10개 확장 후 최종 검증은 아래 기록을 따른다.
- 실제 익명 `PostList.naver` 응답 349,689바이트를 새 파서로 해석해 최근 글 3개의 정규 URL·제목·상대/절대 날짜를 확인했다. 본문 발췌는 결과에 포함하지 않는다.
- 공개 검색에서 `연애`를 최근 작성일순으로 조회했다. 첫 페이지 10개와 둘째 페이지 10개가 날짜 내림차순으로 이어졌다.
- 빌드한 UI에 실제 공개 HTML을 반환하는 Chrome 메시지 모의를 연결했다. 진입 전 최근 조회 0회, 진입 후 1회, 새로고침 후 2회. 검색 10개→20개 추가와 최근 글 3개로 복귀, 검색어 초기화를 확인했다.
- 360×800 화면에서 가로 넘침과 JavaScript 오류가 없었다. 미리보기 삽입은 기존 요청 전달·중복 방지·커서 조건 자동 테스트로 확인했다. 설치된 확장을 교체해 실제 네이버 편집기에 새 링크를 삽입하는 작업은 수행하지 않았다.
- 권한은 기존 `storage`, `sidePanel`과 네이버 블로그 두 호스트를 유지한다. 별도 서버·API 키·DB 변경은 없다.

## 최근 글 10개 확장 검증 (2026-10-29)

- `loadRecentBlog`와 `fetchRecentBlogHtml`의 실제 코드를 사용해 네이버 공개 목록을 익명·캐시 없이 조회했다. DOM 파싱 환경과 Chrome 메시지 전달만 로컬 모의로 연결했다.
- 사용자 블로그는 요청 페이지 `[1, 2, 3, 4]`에서 최근 공개 글 10개를 반환했다. 고유 URL도 10개이며 이후 페이지는 요청하지 않았다.
- 당시 요청·파싱 총 소요 시간은 약 1.15초였다. 속도는 네이버 응답과 네트워크 상태에 따라 달라진다.
- 첫 글 ID `224457248111`, 열 번째 글 ID `224454492477`. 공지글을 제외하고 네이버의 최신순 페이지 순서를 유지했다.
- 자동 테스트에서 3개씩 4페이지→10개, 10개 미만 블로그, 첫 페이지 10개 초과, 페이지 간 중복, 다음 페이지 오류·반복, 잘못된 페이지 요청 차단, 화면의 10개 표시를 확인했다.
- 최종 `npm run release`: 46개 테스트 파일·644개 테스트, 타입 검사, 빌드, 패키지 검증, ZIP 생성이 모두 통과했다. 설치용 1.0.3 ZIP을 같은 경로로 다시 생성했다. 기존 배포 1.0.2는 변경하지 않는다.
