# Design

## Context
동기는 proposal.md를 따른다. 잠금 파일은 Vitest 4.1.11, @vitest/mocker 4.1.11, jsdom 29.1.1 → undici 7.30.0이다. 공식 수정 버전은 Vitest/mocker 4.1.12와 undici 7.30.1이다. 기존 1.2.0 ZIP과 dist의 SHA-256을 업데이트 전 보존했다.

## Goals / Non-Goals
개발 의존성의 audit 취약점 제거와 재현 가능한 잠금 설치를 검증한다. 기존 기능·런타임 의존성·이미 업로드한 패키지와 버전은 유지한다. 외부 스토어 작업은 실행하지 않는다.

## Decisions
- 패치 범위로 Vitest를 ^4.1.12로 올리고 관련 @vitest 패키지를 일치시킨다. jsdom의 허용 범위 ^7.25.0 내에서 undici를 7.30.2로 잠근다. 7.30.1 이후의 추가 보안 수정 6건을 공식 릴리스에서 확인했다. Vitest의 전이 타입 의존성 재해결로 @types/estree 1.0.9→1.0.10도 갱신된다. 직접 undici 의존성이나 override를 추가할 필요는 없다.
- 전역 npm 업데이트, 모든 오래된 패키지 최신화, 강제 audit fix는 범위 밖이다. 관련 없는 런타임 패키지의 변경 여부를 업데이트 전 잠금 파일과 비교한다.
- npm ci로 잠금 파일을 재설치한 후 audit·check·test·build·verify·별도 진단·spec:check를 실행한다. 기존 ZIP은 재생성하지 않고 재빌드 파일을 원본 ZIP과 바이트 단위로 비교한다.
- 사용자의 스토어 업로드·임시저장은 사용자 보고로 표시한다. 실제 대시보드나 업로드 파일 해시는 독립 확인하지 않았으므로 확인했다고 쓰지 않는다.

## Risks / Trade-offs
테스트 실행 환경의 회귀 → 전체 739개 회귀 검사와 별도 진단을 재실행한다.
관련 없는 npm 잠금 변경 → 모든 버전 변경과 prod 항목을 비교한다.
재빌드 차이로 기존 업로드 패키지와 혼동 → 파일별 내용·기존 ZIP 해시를 비교하고 차이를 명시한다. 원본 아카이브를 덮어쓰지 않는다.

## Migration Plan
원본 체크아웃에서 개발 의존성만 업데이트한다. 실패 시 이번에 바뀐 버전 항목만 업데이트 전 기준으로 복원하며 앞선 1.2.0 미커밋 변경은 보존한다. 제품 버전 변경이나 저장 자료 마이그레이션은 없다.
