# Design

## Context
근거는 기존 검수/성능 보고서와 proposal.md를 따른다. 사용자 지시로 로컬 테스트 버전을 1.2.0으로 준비하며, 기존 1.1.2의 기능 호환·권한·로컬 데이터 형식을 유지한다.

## Goals / Non-Goals
빠른 드래그/서식/후속 입력의 체감 지연을 줄이며 기존 원문·사진·직접 입력·undo 검증을 유지한다. 무확인 네이티브 재전송, 임의 큐 재실행, 스토어 제출, 공개 발행은 하지 않는다.

## Decisions
- 패널은 단축키 수신 즉시 순서 토큰을 확보하고 창 확인 이후에도 토큰을 검증한다. 로컬 작업은 요청 시작 문서와 현재 문서를 비교한다. 연결 조회는 bounded throttle과 단일 in-flight 요청으로 관리한다.
- RulesEditor는 아직 저장 중인 조작을 즉시 표시하고 확인된 props와 순서대로 조정한다. 실패는 저장 계층에서 전파하고 실제 저장 상태로 복원한다.
- 선택 추적에 한해 변경 기록으로 무효화하는 내용 재사용을 사용한다. 편집 guard·후조건·undo의 전체 read는 그대로 유지한다. 동일한 선택의 알림을 중복 전송하지 않는다.
- caret 후보는 공개 좌표의 줄/근처 경계로 좁히고 모호하면 기존 전체 탐색/거부로 폴백한다. 좌표 일치 검증은 유지한다.
- 복원 직후 오래된 DOM 앵커는 선택된 네이티브 원문과 유일한 본문 하이라이트의 정확한 기하 일치로만 보완한다. 양방향 문단은 비인접 오프셋의 모호성도 전체 탐색으로 확인한다.
- 네이티브 서식은 속성별 안정화 검증을 유지하되 마지막 100ms를 제거한다. 실제 네이티브 도구 실행 후 완전한 후조건이 충족된 상태에서 입력/다음 요청이 오면 대기를 깨우고 더 이상의 도구 실행 없이 완료한다. 그 후 직접 입력이 있으면 undo를 비활성화한다. 부분 적용은 기존 복구 경로를 유지한다.
- 다음 요청을 넘겨받을 때 선택·세션·revision이 바뀌면 재선택을 요청한다. 검증 전 작업을 자동 큐잉하지 않는다.
- 단축키용 저장 읽기는 매 실행 최신 값을 읽고 설정·프리셋만 검증한다. 전체 DB/백업의 기존 검증은 유지한다.

## Risks / Trade-offs
선택 내용 재사용의 무효화 누락 → DOM 변경·제거·사진·제목·상속 스타일 테스트 및 핵심 검증의 fresh read 유지.
입력과 비동기 네이티브 변경 경쟁 → 전체 후조건 확인 이전에는 handoff하지 않으며 native 지연/부분 적용/사용자 직접 입력 회귀 검사.
성능 수치 환경 차이 → 동일 로컬 계측 전후 비교와 실제 네이버 설치본 결과를 구분해 기록.

## Migration Plan
새 schema/권한/데이터 변환 없이 빌드하여 로컬 설치본에서 확인한다. 회귀 시 관련 소스 변경을 되돌릴 수 있도록 검수 자료를 보존한다. 버전 공개/스토어 상태를 임의로 갱신하지 않는다.
